# Open-field PvE v1

The Ruins coordinator owns eight catalogued spawn points. Existing `GameSimulation` enemy AI, player weapons, projectile/area damage and effects run at 25 Hz. No WaveDirector, run timer completion, temporary XP, level-up choices or Survivor drops run in this activity. Refuge and the 200-unit Ruins entrance are safe. Dead players return to the entrance after five seconds; the region and other presences continue.

Each occurrence has a private UUID. Respawn takes at least 45 seconds. Spawns require nearby living players, enemies leash to their camp, and the evidence queue is bounded to 64. Spawn production pauses before a persistence backlog can overflow. Server damage records contributors; only living contributors still in that occurrence's region/visit and within 720 units are eligible. Group membership alone never grants credit.

Only `FIELD_ENEMY_DEFEAT` is supported. It does not masquerade as an expedition completion, elite/boss quest objective or Survivor kill reward. The coordinator creates the event's private crypto seed and immutable proof, persists them, and then settles using a dedicated event/participant receipt. Crash before evidence is durable loses that unconfirmed result. Crash after durability is recovered from `PENDING`; crash after settlement returns the existing receipts.

Version 1 grants at most twenty field rewards per UTC account day: three permanent XP and one Obelisk Dust each. The first eligible reward additionally grants one level-one common Weathered Blade, unequipped. These conservative initial limits are catalogued, not client values. Equipment uses the existing affix roller and a domain-separated HMAC seed. Reconnecting/changing visits does not reset account limits. XP uses the existing progression/attribute-budget function and preserves spent points. Combat builds refresh in the Refuge; the field build remains frozen until returning.

Each settlement locks the event then UserProgress rows in sorted user order and commits character/material/item/profile-revision/receipts atomically under Serializable isolation. Only known aborted serialization failures retry. It never increments UserProgress.version and never calls legacy settlement. Public projections omit private seeds, visits and authority IDs. The HUD and paginated rewards panel use persisted results.

Validation performed: PostgreSQL concurrency, idempotent replay, rollback after material write, recovery after disconnect, level advancement, daily limits, foreign provenance rejection, flag rejection and paginated ownership. A real six-account WebSocket scenario navigates to a camp, earns a real item and XP, replays settlement without duplication, and gathers a material afterward. Unit simulation covers weapons, evidence, defeat/respawn and safe Refuge. Final browser/performance/regression results belong in the phase QA report.
